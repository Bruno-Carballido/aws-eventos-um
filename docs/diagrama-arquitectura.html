Diagrama de arquitectura ECS · Sistema de inscripción y recordatorios para eventos

Cómo viaja una solicitud desde el navegador hasta DynamoDB y SNS, y dónde corre el planificador

Escalado (1 a 3 tareas por CPU 60 %)

  • • Servicio ECS con 1 tarea al inicio.
  • • Application Auto Scaling entre 1 y 3 tareas.
  • • Objetivo de CPU promedio del 60 %.
  • • Cooldown de 60 s para subir y 300 s para bajar.
  • • En la prueba con 60 conexiones paralelas, el CPU llegó a 75-83 % y el servicio pasó de 1 a 3 tareas.

Recordatorios

  • • Un planificador APScheduler corre dentro de cada tarea, cada 1 hora.
  • • Busca eventos de las próximas 24 horas y publica el recordatorio por SNS.
  • • El reclamo condicional en DynamoDB evita envíos duplicados entre tareas.
  • • Si la publicación falla, la marca se libera y se reintenta en la próxima hora.

Sin Lambda ni API Gateway

  • • Todo el cómputo corre en tareas Fargate detrás de un ALB público.
  • • Las tareas viven en subredes privadas sin ruta a Internet y sin NAT.
  • • S3, DynamoDB, ECR, CloudWatch y SNS se alcanzan por endpoints de VPC.
  • • La API no tiene autenticación y el ALB usa HTTP.
